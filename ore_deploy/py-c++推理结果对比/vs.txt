## 数据分析（论文可以直接写）

1. **推理 Run 阶段收益最大**：C++‑ONNX Runtime 消除 Python GIL、numpy 对象拷贝开销，推理部分从 91.75ms 下降至 54.42ms，是整套提速核心来源。
2. **预处理 Python 更快**：Python 使用 numpy 高度优化向量化算子；C++ 实现是普通 for 循环 HWC→CHW 拷贝，如果追求进一步提速，可以替换成 cv::split /cv::merge 优化。
3. **后处理**：当前测试集目标数量少，C++ 表现更好；**当一张图大量实例时，手写 mask 解码三重循环会成为瓶颈**，后面迁移 TensorRT 之后可以把 mask 相关计算移到 GPU。
4. **整体端到端**：C++ 版本全套 96.37ms，相比 Python159.36ms，端到端提速接近 40%，体现 C++ 部署在端侧推理的价值。

> 
> 面试可以讲：Python 适合算法原型快速迭代；C++ 部署消除解释器开销，推理本体获得明显性能收益，但手写朴素循环部分存在优化空间。

表格表格**C++ TensorRT 最快，全套 38 ms，是 Python 版的 4.2 倍。**

## 分阶段看点

1. **推理是最大分水岭**：Python 91.8 ms → C++ ORT 54.4 ms → TRT 9.0 ms。TRT 的 FP16 + 层融合 + 专用内核把推理压到了 1/10。
2. **后处理 C++ 两版几乎一样**（18.0 vs 18.5 ms），Python 最慢（41.9 ms）—— 因为 NMS + mask 是纯 CPU 循环，Python 循环开销大。
3. **预处理反直觉**：Python（6.7 ms）比 C++ ORT（12.4 ms）还快，说明 C++ ORT 版的预处理实现有优化空间（可能做了多余的拷贝或逐像素循环）；TRT 版用 OpenCV 向量化只要 2.1 ms。
4. **TRT 版当前瓶颈是后处理**（18.5 ms，占全套 49%），推理只要 9 ms。如果要继续提速，应该把 mask 计算搬到 GPU，或降低 mask 分辨率。

如果你的部署目标是**实时性**，C++ TensorRT 是明确选择；如果追求**开发效率**且对延迟不敏感，Python ORT 也够用。
